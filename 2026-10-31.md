# 31 Oct 2026: Payment gateways from the admin panel

**Short version:** the payment gateway (Razorpay, Cashfree) is now switched on and off from the admin panel, with its keys typed in there. The app asks the API which gateway is on and gets its public key from there, so nothing about the gateway is hardcoded in the app any more.

**Who has to act:** the customer app team, and whoever holds the gateway accounts (to enter the keys).

---

## For the admin

**Admin → Payment methods → Payment gateways**

1. Press **Keys** on a gateway and paste its keys. They are stored encrypted. Saved secrets show as dots, and a blank field keeps what is saved.
2. Press **Test**. This only checks that the gateway accepts the keys. Nothing is charged.
3. Press **Turn on**. Only one gateway can be on: turning one on turns the others off.
4. Copy the **Webhook URL** shown on the row into the gateway's dashboard. Without it, an order is only marked paid when the app reports back.

| Gateway | Keys | Test / live |
|---|---|---|
| Razorpay | Key ID, Key secret, Webhook secret | Decided by the key (`rzp_test_…` / `rzp_live_…`) |
| Cashfree | App ID, Secret key | A Mode switch on the form (sandbox vs production keys) |

> **With no gateway on, UPI/card/net-banking orders are marked paid without any money being collected.** That is how production runs today. The panel shows a warning for as long as it stays that way.

## New API (no token needed)

```
GET /api/customer/payments/config
```

```json
{ "data": { "enabled": true, "gateway": "razorpay", "name": "Razorpay", "mode": "live",
            "config": { "key": "rzp_live_XXXXXXXX" } } }
```

- `config` holds **only the public key**. The key secret never comes to the app, and must not be put in the app.
- For Cashfree, `config` is `{ "environment": "SANDBOX" }` or `PRODUCTION`. Cashfree needs no key on the phone.
- `enabled: false` means no gateway is on. Online orders are settled on placement and the app opens no SDK.
- The same block also comes back as `payment_gateway` on `GET /api/customer/checkout`.

## Changes to paying

`POST /api/customer/payments/create-intent` now also returns:

- `gateway`: `razorpay` or `cashfree`. This says which SDK to open.
- `mode`: `test` or `live`.
- `checkout`: exactly what that SDK needs. Pass it through as it is.
  - Razorpay: `key`, `order_id`, `amount` (paise), `currency`, `name`, `description`, `prefill`
  - Cashfree: `payment_session_id`, `order_id`, `environment`
- `amount` is now **what is left after store credit**, not the whole `grand_total`.

`POST /api/customer/payments/verify`:

- Razorpay: same as before (`razorpay_order_id`, `razorpay_payment_id`, `razorpay_signature`).
- Cashfree: send only `{ "order_number": "1043" }`. The server checks with Cashfree. A `422` with "not received yet" means retry in a few seconds.

**Nothing breaks.** The fields the Razorpay flow already uses (`key`, `gateway_order_id`, the three `razorpay_*` fields, the webhook URL) are unchanged.

## What the app should do

1. Read `gateway` from `/payments/config` or `checkout.payment_gateway`. Do not hardcode Razorpay or its key.
2. After `POST /orders`, if `payment_required` is `true`, call `create-intent` and open the SDK named by **its** `gateway`, passing `checkout`.
3. On the SDK's success callback, call `verify`: the three `razorpay_*` fields for Razorpay, or `order_number` for Cashfree.
4. Show `amount` from `create-intent` as the amount being charged.
